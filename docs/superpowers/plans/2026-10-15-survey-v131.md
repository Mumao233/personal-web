# Survey v1.3.1 Implementation Plan

**Goal:** Add a standalone survey entry and consistent option normalization with actionable errors while preserving historical data.

**Architecture:** Derive entry mode synchronously from the URL and keep successful submission state scoped to one route visit. Share a pure survey definition normalizer and issue collector between editor and backend. Keep transaction, revision and idempotency protections in existing write paths.

**Tech Stack:** React 19, Vite, Express 5, Node SQLite, node:test, jsdom and Chrome/Playwright for isolated acceptance.

## 1. Shared definition rules and persistence

- [x] Create `shared/survey-definition.js`: immutable `normalizeSurveyDefinition`, newline-preserving `splitOptionLines`, structured `surveyDefinitionIssues`.
- [x] Test empty/whitespace rows, LF/CRLF, all five option question types, no nonblank trimming, duplicate/length/count errors and multiple errors.
- [x] Update `server/validation.js` and save callers in `server/index.js` / assistant services to use normalized values and structured errors.
- [x] Check previous definitions and saved answers under the existing transaction. Reject unmappable answered option/row/question changes; preserve exact text and statistics for retained values.
- [x] Run targeted Node tests for validation, API persistence, snapshots, statistics, references, and revision conflicts.

## 2. Editor and links

- [x] Update `src/admin.jsx`: preserve raw textarea, normalize preview/save copies, display issue summary and links to stable question/field targets.
- [x] Propagate issue arrays in `src/api.js`; retain unsaved values on all failures. Do not silently prune invalid rules during option edits.
- [x] Provide two explicit copy actions with ordinary and `standalone=1` URLs.
- [x] Add jsdom interaction tests for typing a final newline, several issues, matrix field focus, server errors and failed-save preservation.

## 3. Independent public entry

- [x] Update `src/main.jsx` to choose the standalone shell before mounting navigation and unrelated modules.
- [x] Add server-success callback to `src/survey.jsx`, guarded by the current visit/questionnaire identity. Leave existing receipt and inflight mechanisms intact.
- [x] Reset successful presentation on route entry/history restoration; reject stale asynchronous callbacks. Do not persist navigation visibility.
- [x] Test first-render absence of navigation DOM, failed submission, success, ordinary entry, refresh/history/survey transitions and preview separation.

## 4. Integration and browser acceptance

- [x] Run `npm test` and `npm run build` from the worktree; resolve all failures.
- [x] Start production build on loopback with a dedicated `.qa` data directory, TEST_MODE=1 and synthetic questionnaire records.

- [x] Review final diff for regressions, untracked data, credentials, source scope and accurate release notes.
