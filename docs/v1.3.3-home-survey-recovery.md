# v1.3.3 首页与问卷恢复更新

本版按用户提供的 v1.3.2 审查材料和需求访谈实施，版本号由用户指定。概念图用作构图参考；保留真实内容、光影主题、六个栏目、菜单动画以及独立的太阳系作品。首页预览在部署前提供，发布仍按既有备份和验收流程执行。

## 首页与导航

- 桌面文字左、真实 WebGL 场景右；手机按照文字、场景、主按钮排列。主按钮进入六栏目探索，次按钮继续阅读。
- 阅读与探索使用同一个场景控制器。退出探索恢复打开按钮的焦点和原阅读位置；快速关闭或重新打开不遗留旧定时器。导航菜单与探索互斥。
- 手机菜单仍为非模态，可阅读未被覆盖的背景；探索是带焦点约束的模态。短屏不挂载可能遮挡按钮的场景浮动标签，仍可使用六栏目普通导航。
- 悬浮探索按钮只在首页首屏之后出现，问卷页不显示。太阳系作品在首页保留视觉入口，完整体验位于 `/solar/`。
- 欢迎动画只在当前标签页首次访问首页时显示，开始即记录已播放，可跳过；刷新及深链接不会重新播放。文案暂停时立即显示完整句子，偏好保存在设备上，减少动态效果时静态显示。

## 问卷填写与恢复

每个标签页默认独立填写，刷新恢复当前实例，恢复其他本机记录需要主动选择。同一份可编辑记录不允许两个页面同时占用。浏览器不支持独占锁时采用独立副本和显式恢复，界面说明刷新恢复与删除的限制。

普通草稿在最后一次编辑 7 天后过期。待确认提交单独保存完整请求和题目快照，不受草稿期限影响，不随另一个标签页保存、清除或成功提交而删除。旧版单条存储迁移后也需显式恢复；缺少安全映射资料的旧记录可下载核对。

提交结果不确定时锁定答案，以原答案、原问卷定义版本和原提交标识重试。此操作可能完成第一次未到达服务器的提交，也可能取得已保存答卷的回执，不是只读查询。只有有效服务端成功响应才解除独立链接的导航限制。

服务器明确报告提交标识已对应不同内容时，保留当前答案，允许下载或经确认开始新一次填写；开始后不自动提交，并说明再次提交会新增答卷和统计记录。问卷版本变化仍要求加载新版，只沿用题目定义完全未改变的答案，并保留更新前副本下载入口。

“不在此设备保存”删除本次填写的设备副本，当前答案及待确认请求只留在页面内存中；刷新或关闭后不能恢复，切换前可下载答案。其他历史记录不受此开关影响。浏览器拒绝删除时明确提示旧内容可能仍在设备上，不把失败声明为已删除。

清除答案和删除恢复记录均需确认。删除本机恢复记录不会撤销服务器可能已经收到的答卷；之后重填可能新增一份答卷。独立问卷是填写展示流程，不是公开主页的访问控制。

## 数据和实现边界

本版不改后端接口、数据结构、依赖版本、问卷定义或发布状态，不批量重写旧答案。已有选项精确文本引用、空行规范化、跳题、互斥、提前结束、历史统计及乐观版本保护继续由共享校验和服务端独立验证。

测试写入只使用隔离 SQLite 数据库、合成问卷和本地浏览器存储；生产仅作读取验证。前端在本地构建后上传，候选应用保留原 Linux 依赖、Atlas、运行缓存及配置。切换前备份一致性数据库、上传文件和旧应用，应用回滚不覆盖当前用户数据。

- 本地 Node 全套 **316/316** 通过；最终恢复记录提示接入后，16 条问卷 UI 测试再次通过。专项包含 29 条存储测试、16 条恢复 UI 测试及既有选项、统计、版本冲突和提交回执回归。本地 Vite 生产构建通过。
- 首页生产构建浏览器验收 14 组通过，覆盖桌面、手机尺寸、菜单键盘、进入/退出探索、焦点/滚动恢复、暂停文案、减少动态效果和 WebGL 失败回退；4 个短屏深浅主题案例复验通过。实际使用 NVIDIA 显卡的 WebGL 渲染；另有 6 组普通/独立问卷导航隔离检查通过。
- 完整 Express/SQLite 隔离服务器上的构建版问卷验收 **20/20** 通过。通过真实服务端保存后丢弃浏览器响应制造响应丢失，核对答卷数量、原始答案和回执摘要，验证重复重试不会新增答卷。
- 最后代码修复后的构建又完成 **10/10** 相关组复验，包含 3 个新增场景：延迟成功/失败 GET 不能污染恢复的待确认请求，提交标识冲突不能借加载新定义或刷新被清除。最终手机深浅主题的恢复列表、待确认和停止保存弹窗完成截图检查。
- 还覆盖复制标签页及离开问卷后复制、当前标签页刷新、不同标签页提交与清除、7 天普通草稿期限、90 天待确认记录保留、主动删除、内存模式刷新丢失、旧版显式恢复和无损导出、问卷关闭/更新后原回执确认、GET 超时重试和切段焦点。

Linux 候选应用、正式服务切换、生产数据保留和版本一致性结果以服务器发布清单及同名 GitHub Release 为准；上述本地结果不代替线上验收。

未进行实体手机、真实屏幕阅读器或真实摄像头手势测试；移动端验证使用 Chrome 的视口与触摸模拟。此更新不宣称覆盖所有浏览器的存储清理策略。
